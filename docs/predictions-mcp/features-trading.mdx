## Placing Trades

Execute real trades on Polymarket. Buy or sell outcome shares.

<Warning>
  Trading uses real money (USDC on Polygon). Always review trade details before confirming.
</Warning>

### By Dollar Amount

```
"bet $5 on eagles to win tonight"
"put $20 on cowboys to win this weekend"
"bet $10 on trump winning the election"
"buy $50 of Yes on the Bitcoin market"
```

### By Shares

```
"buy 100 shares of YES in the bitcoin market"
"buy 50 NO shares for the fed rate decision"
"sell 25 shares of my Lakers position"
```

### Limit Orders

```
"buy Yes at 0.40 or better on the Trump market"
"place a limit order for No at 0.25"
"buy Yes shares but avoid slippage"
```

## Understanding Outcomes

- **Yes price of $0.70** = 70% implied probability of happening
- **No price** is always (1 − Yes price)
- Winning shares pay out **$1.00 each**
- Your profit = $1.00 − purchase price per share

### Example

If you buy 100 Yes shares at $0.40 each:

- **Cost:** $40
- **If Yes wins:** you get $100 → **$60 profit**
- **If No wins:** shares worth $0 → **$40 loss**

## Check that it works

Check the trade tools without placing a trade. Call the native `splitMergePredictionPosition` tool without `authorized`, using a `conditionId` from `getPolymarketPositions` or `resolvePredictionMarketExact`:

```json
{ "operation": "split", "conditionId": "0x...", "amount": "1" }
```

Expected: a preview that sends nothing and carries a `next` suggestion for the confirmed split. A native `tradePredictionMarket` call places an order only after you give an explicit instruction. Prices use real USDC on Polygon.

## Split, merge, and convert positions

- **Split** uses `splitMergePredictionPosition` to turn pUSD into equal YES and NO shares on one market. A split without `authorized` previews the action and sends nothing.
- **Merge** uses the same tool to turn equal YES and NO shares on one market back into pUSD. A direct merge request is execution intent; it does not have the split's `authorized` preview requirement. The tool is destructive and host approval still applies.
- **Convert** uses `convertPredictionPosition` to turn NO shares on one market of an eligible negative-risk, one-winner event into YES shares on every other market in that event. Each receives the converted amount less any event fee; this is not a merge into pUSD.

For conversion, use the source market's `conditionId` from `getPolymarketPositions` and an `amount` as a decimal string or `"max"` for all held NO shares. Call without `authorized` to preview without sending. Review the source, each output, the fee and any included approvals. After confirmation, call again with `authorized: true`. The preview carries a typed `next` suggestion for that call with an editable amount and host approval. A split preview similarly suggests the authorized split. The server never executes a suggestion.

The tool checks eligibility rather than assuming every multi-outcome event qualifies. Conversion requires held NO shares and a supported negative-risk position system; Polymarket V2 markets are not supported. It refuses closed or resolved source markets and events whose outcomes cannot all be verified as named, active, open and matching their onchain tokens, including placeholders. If the source market is closed, the result can suggest `redeemPredictionMarket` for its condition instead. Redemption is for eligible winning shares, not a conversion.

If an operation reports an unknown outcome, it may have landed: check `getPolymarketPositions` before trying again. Also check positions before acting again if conversion succeeds but reports `verified: false`. When retrying after a timeout or error, use the same `idempotencyKey` as the original attempt.
