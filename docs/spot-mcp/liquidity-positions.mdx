## Discover and select

1. Read `getAccountAddresses` and `getCrosschainPortfolio` for wallet identity and available balances.
2. Read `getLpPositions` for Robinhood Chain, or `getSolanaLpPositions` for Solana. Follow returned inventory cursors and preserve partial coverage, unread positions and source times.
3. Select the exact pool and position. `resolveSolanaLpPool` returns candidates from a mint or pool address; it neither selects one nor admits it.
4. Check `getLpAllowlist` or `getSolanaLpAllowlist`. Each user has separate EVM and Solana admission lists and revisions.

Admission updates use different identity fields:

- EVM: `updateLpAllowlist` takes `action: "add"` with the full `pool`, or `action: "remove"` with the entry's `poolKey`.
- Solana: `updateSolanaLpAllowlist` takes `protocol`, `poolAddress` and `action: "add"` or `"remove"`. Adding checks the pool's on-chain program owner.

Both require the current `expectedRevision`. Re-read on a revision conflict. Revocation blocks new exposure, including recentering; supported reductions remain available: decrease, collect and close, plus CPMM withdraw.

Keep chain ID, wallet, protocol, pool and position identifiers intact. Uniswap token IDs and position-manager addresses are distinct from v4 pool IDs and pool keys. Raydium uses pool, mint, token-account and position addresses. A foreign EVM position may be observable; visibility never grants permission to operate it.

## Fund and quote

Both assets must cover the intended operation. LP quotes do not swap into the desired ratio. Preparatory swaps are separate transactions: reconcile them before requesting a fresh LP quote. Uncollected position assets are not spendable wallet balances.

For EVM, `quoteLpOperation` requires `funding`: delegated `account`, `chainId: 4663`, authorized `fee` alternatives, `assetCeilings` and retained-balance `reserves`. A fee alternative is `sponsored` or `fee-token` with `asset` and `maxWeiAmount`. There is no implicit paid fallback. Duplicate assets or a different wallet/chain are refused. Unknown costs are not zero fees.

For Solana, `quoteSolanaLpOperation` binds the selected pool, position, wallet, allowlist revision and slot window. Supply the last read `expectedRevision` to detect admission changes. Review token maximums, receive minimums and other returned constraints. Keep SOL for fees and account creation. The compiler can wrap native SOL to cover a WSOL funding shortfall; inspect `wrapsNativeSol`. Receiving native SOL instead of WSOL requires `unwrapWsolToNative: true`, supported for withdraw, decrease, collect and recenter. Review `unwrapsWsolToNative` in the quote.

A live Token-2022 transfer-hook program is refused, even if the token can be swapped. An empty transfer-hook slot can be supported. Other token-program and extension checks still apply; a successful swap is not proof of LP compatibility. Follow the quote's refusal instead of repeatedly sending the same unsupported request.

### Read and quote examples

The examples below are templates, checked against the pinned input schemas with synthetic test substitutions. Angle-bracket strings must be replaced with identities from your wallet and pool reads; they are deliberately not runnable addresses. Schema checks do not prove admission, balances, pool ownership or execution. Use a real admitted pool for new exposure, and inspect the current published schema before sending.

Raw amounts are decimal strings in the token's smallest units. `"1000000"` is one token only when it has six decimals. LP-token amounts and liquidity units have their own protocol meaning.

{/* lp-example: evm-read */}

```json
{ "protocol": "uniswap-v3" }
```

Call `getLpPositions` with the input above; use `"uniswap-v4"` for v4. Call `getSolanaLpPositions` with:

{/* lp-example: solana-read */}

```json
{ "analytics": true }
```

```json
{
  "kind": "increase",
  "position": {
    "chainId": 4663,
    "protocol": "uniswap-v3",

    "tokenId": "<position-token-id>"

  "amount0Desired": "1000000",
  "amount1Desired": "1000000",
  "funding": {
    "account": "<delegated-evm-wallet>",
    "chainId": 4663,

```

## Execute the exact quote

Keep `intentId`, `quoteId` and `planHash`. `intentId` identifies the intended action; `quoteId` identifies its current quote; `planHash` binds the plan. Review amounts, fees, minimum receive bounds and expiry before authorizing execution.

Call `executeLpOperation` or `executeSolanaLpOperation` with the exact returned `quoteId` and `planHash` only when execution is authorized. Quoting signs and sends nothing. A quote request alone does not authorize execution.

To refresh an unexecuted intent, pass its `intentId` to the quote tool. The new `quoteId` supersedes the old one: never execute the old quote. An outstanding send blocks re-quoting. EVM quotes expire by their stated deadline; Solana quotes have an `expiresAtSlot` window. A replacement quote must be reviewed again if material terms change.

## Recover an uncertain operation

Keep the returned `operationId`, quote identity and any attributable transaction reference. Read `getLpOperationStatus` by `operationId` or the exact claiming `quoteId`. Read `getSolanaLpOperationStatus` by `operationId`.

If those handles were lost, call the relevant status tool with:

{/* lp-example: unresolved */}

```json
{ "unresolved": true, "limit": 10 }
```

Follow each returned `nextCursor` using `cursor` until null. The listing is bounded; a single page is not all outstanding operations. Native results expose `operations` and `nextCursor` directly; sandbox results wrap them under `data`. Rows may settle during reconciliation or remain unavailable.

Prepared, submitted and pending are not settled. Unknown or partial results require reconciliation of receipts, position state and attributable asset flows. A timeout, missing receipt or successful outer shell command does not prove whether funds moved. Never automatically resend, replace an unknown send or repeat a settled leg. Only authoritative resolution can establish whether a distinct new attempt is eligible.

## Widgets and text clients

Compatible clients can render LP positions and quote/status widgets. Clients without widgets still receive the tool's structured/text result, identifiers, constraints and recovery steps. Rendering a card changes presentation, not transaction authority; an Execute control must use the current bound quote and the user's authorization.
