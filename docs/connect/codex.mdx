You need the Codex CLI and a browser to complete the Ask Gina sign-in.

Add the remote server using the Codex CLI:

```sh
codex mcp add ask-gina --url https://askgina.ai/ai/gina/mcp
codex mcp login ask-gina
```

The login command opens the OAuth flow. Complete it in the browser, then start or refresh your Codex session.

Alternatively, merge this entry into your Codex MCP configuration:

```toml
[mcp_servers.ask-gina]
url = "https://askgina.ai/ai/gina/mcp"
```

Use the login command after configuring the server. Do not overwrite your other MCP settings. See [Codex MCP configuration](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

## Add research skills

The direct connection provides tools. To get the research skills too, install the plugin from the repository marketplace. See [install for your host](/agents/plugins-and-skills#codex) for the commands.

To load skills by hand instead, copy the complete directories of the [research skills in the catalog](/agents/skills-catalog) from `plugins/ask-gina/skills/` in [the source repository](https://github.com/askgina/plugins/tree/main/plugins/ask-gina/skills) into your project's `.agents/skills/` directory. Start a new session and confirm Codex lists them. Do not replace existing unrelated skills.

## Add the Predictions connector

Prediction trading and prediction events use a second server, separate from Gina Read. It requests `tools:execute`, so it is write access (Degen mode). Creating an event subscription also needs a finished Predictions account with delegated signing in Ask Gina; without it the tool fails with `PREDICTION_EVENTS_ACCOUNT_NOT_READY`.

```sh
codex mcp add predictions --url https://askgina.ai/ai/predictions/mcp
codex mcp login predictions
```

The login command opens the same browser sign-in. Complete it, then start or refresh your Codex session. Keep the `ask-gina` entry for research. The [Predictions client setup](/predictions-mcp/client-setup#codex) has the matching configuration entry.

Codex cannot receive a webhook, so it reads prediction events by cursor, with no destination and no browser step. Create a subscription with `createPredictionEventSubscription` and no `destinationId`, then call `getPredictionEvents` with the returned `subscriptionId` and `cursor`, and pass each new `cursor` back to read only newer events. Dedupe on `eventId`. The steps and recovery are in [Prediction events](/predictions-mcp/events#pull-events-with-a-cursor-codex-and-other-clients). To push events to an HTTPS receiver you run, Codex can register it with `createWebhookDestination`, test it with `sendWebhookTestEvent` and then pass its `destinationId`. See [With MCP tools](/predictions-mcp/events#with-mcp-tools).

To check the connection, confirm that `listPredictionEventSubscriptions` and `getPredictionEvents` appear in the Codex tool list, then ask Codex to list your prediction event subscriptions with `listPredictionEventSubscriptions`. It is a read, so it changes nothing.

## Verify your first result

1. Open the Codex tool list for `ask-gina`. It shows named read tools such as `getSimplePrice`, `getTokenChart` and `getAccountAddresses` (a host may add a prefix) and no `bash`.
2. Ask **“Use Gina to show ETH in USD over the past seven days.”** Confirm a Gina tool ran and the response identifies ETH and the requested period. An answer from the model's memory is not a successful connection test.

If sign-in fails, run `codex mcp login ask-gina` again. If no tools appear, refresh the tool list or start a new Codex session. [First successful request](/start/first-request) has the same steps with more detail.

The `ask-gina` connection is read-only. For trading or transfers, see [Write access (Degen mode)](/write-access/index). A direct connection does not automatically install [research skills](/agents/plugins-and-skills).
