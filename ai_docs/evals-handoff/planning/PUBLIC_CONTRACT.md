# Public eval contract v1

This handoff describes conformance, not answer accuracy, profitability, financial execution or settlement. Examples in `fixtures/` are synthetic development data. No measured result or publication approval is claimed. The TypeScript implementation is `packages/contracts/src/eval-results.ts`, re-exported by the package root.

## API boundary

Import runtime schemas only in the Node/Bun framework or exporter. Existing package guarantees are unchanged: no browser, edge or package-subpath runtime imports. A browser may use erased `import type { PublicEvalResult, PublicEvalPublication, PublicEvalIndex } from "@askgina/contracts"` and consume serialized JSON. It does not grade, approve, sanitize or calculate eligibility.

Exported schema/type pairs are `PublicEvalAttemptSummarySchema`/`PublicEvalAttemptSummary`, `PublicEvalAttemptCaptureSchema`/`PublicEvalAttemptCapture`, `PublicEvalResultSchema`/`PublicEvalResult`, `PublicEvalPublicationSchema`/`PublicEvalPublication`, and `PublicEvalIndexSchema`/`PublicEvalIndex`.

The four one-argument functions `decodePublicEvalAttemptCapture(input)`, `decodePublicEvalResult(input)`, `decodePublicEvalPublication(input)` and `decodePublicEvalIndex(input)` return `Effect.Effect<DecodedType, Schema.SchemaError>`. They use prebuilt private decoders with `errors: "all"` and `onExcessProperty: "error"`. Unknown fields fail at every nested object. There is no per-call option override. Raw Effect schemas are reusable but their default decode strips unknown fields; callers using raw schemas must pass `PUBLIC_EVAL_DECODE_OPTIONS`.

Supporting exports include identifier/hash/timestamp, check-verdict, failure-category, attempt-check and token-usage schemas; inferred check/token types; the `PUBLIC_EVAL_*` literal lists; `PUBLIC_EVAL_MAX_ATTEMPTS` set to 5,000 for shared preflight bounds; `publicEvalFailureCategories(checks)`; and `publicEvalAttemptIdentityInput(runId, caseId, repetition)`.

## Attempt summary and capture

The shape is exactly the shared attempt contract in `IMPLEMENTATION_CONTRACT.md`.

| Field                                               | Meaning                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                                                | `attempt-` plus lowercase SHA-256 of UTF-8 `JSON.stringify([runId, caseId, repetition])`. The exported identity helper returns that preimage. The shared schema checks the canonical digest, including direct publication-library calls; a unique, correctly formatted but noncanonical digest is rejected. |
| `runId`, `caseId`, `repetition`                     | Public identity and positive planned repetition. Earlier failures remain present when a later repetition passes.                                                                                                                                                                                            |
| `verdict`                                           | Existing grader's `pass` or `fail`, not a new grading rubric.                                                                                                                                                                                                                                               |
| `validity`, `evidenceAvailability`, `replacementOf` | Literals `valid`, `available`, `null`. Availability means retained check summaries, never verified financial evidence.                                                                                                                                                                                      |
| `checks`                                            | Exactly `routing`, `arguments`, `safety`, `completion`, `skillActivation`; each `pass`, `fail` or `not_applicable`. Missing optional grader dimensions map to `not_applicable`.                                                                                                                             |
| `failureCategories`                                 | Exact failed-check categories in check order: `routing_mismatch`, `argument_mismatch`, `safety_violation`, `trial_or_tool_failure`, `skill_activation_mismatch`. No free-form grader text.                                                                                                                  |
| `durationMs`, `tokenUsage`                          | Nonnegative integer milliseconds; token usage is null or nonnegative integer `inputTokens`, `outputTokens`, `totalTokens`. Existing eval schemas do not require input plus output to equal total; no new accounting rule is introduced.                                                                     |

A capture is `{schemaVersion:"eval-attempts.v1", runId, sourceReportSha256, attempts}`. The report digest binds the exact saved sanitized report bytes, including trailing newline. All attempts have the same run ID; duplicate IDs and duplicate case/repetition tuples fail. Capture is a private/sanitized companion artifact, not measurement attestation or publication approval. It intentionally has no extra `dataOrigin` field; synthetic examples retain that label through their filename and run/case IDs.

V1 does not accept invalid attempts or scoring replacements. A later replacement contract would need predeclared versioned invalidation rules, an applicable reason, evidence, Eric's recorded approval, the original attempt, and the replacement link. A failed or blocked trial is not infrastructure invalidity.

## Result JSON

All listed keys are required; explicit nulls carry absence. `schemaVersion` is `eval-result.v1`; `measures` is `conformance`. `resultId` is a public identifier and `dataOrigin` is `synthetic` or `measured`.

| Object                   | Fields and interpretation                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `run`                    | `runId`, UTC `startedAt`.                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `source`                 | `kind: sanitized_aggregate \| sanitized_aggregate_with_attempts`, `reportSchemaVersion:"v1"`, `reportSha256`, `attemptCaptureSha256:null \| hash`. The detailed kind and nonnull companion digest are present exactly when public attempts are present. Withheld or discarded detail does not expose its private companion digest.                                                                                                                 |
| `benchmark`              | `suiteId`, `suiteVersion`, `fixtureVersion`, `catalogSha`, `target`, `accountClass`, `cleanChat:true`, `repetitions`. These identify declared benchmark conditions, including repetitions rather than just a model name.                                                                                                                                                                                                                           |
| `configuration`          | `availability:pinned \| labels_only`, `candidate`, `model`, `reasoning:null \| identifier`, `pinnedSha256:null \| hash`. A pin identifies separately declared system configuration bytes. Labels alone do not establish a reproducible configuration.                                                                                                                                                                                              |
| `coverage`               | `planSource:run_manifest \| declared_plan`, `planSha256`, `statusSha256`, `status:complete \| incomplete`, `plannedCases`, `plannedAttempts`. Planned attempts equal planned cases times repetitions. `run_manifest` means the existing complete-run sanitizer gate was satisfied; both external hashes are null. `declared_plan` requires hashes of an independently authoritative plan and status source. It is not inferred from missing files. |
| `counts.attempts`        | `total`, `passed`, `failed`; passed plus failed equals total. These are observed counts, not an incomplete-cohort headline score.                                                                                                                                                                                                                                                                                                                  |
| `counts.cases`           | `total` distinct observed cases; `passedEveryAttempt` and `failedAnyAttempt` are null unless all attempts are retained and coverage is complete. No per-case verdicts are reconstructed from legacy aggregates.                                                                                                                                                                                                                                    |
| `dimensions`             | The five check keys, each `{passed,failed,notApplicable}`. The sum equals observed attempt count. Routing, arguments and completion have no not-applicable observations in the existing grader. Each failed count is at most overall failed attempts; every failed attempt requires at least one failed dimension.                                                                                                                                 |
| `metrics`                | See below.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `evidence.attemptDetail` | `available`, `aggregate_only`, `not_retained`, `withheld`, `not_evaluated`, or `not_applicable`. These concern detail availability, independent of a conformance verdict.                                                                                                                                                                                                                                                                          |
| `ranking`                | `status:"unranked"`; `reasons` is exactly `pilot`, then applicable `synthetic`, `incomplete_coverage`, `missing_pinned_configuration`, in that order. No rank, confidence policy or true eligibility flag exists.                                                                                                                                                                                                                                  |
| `attempts`               | Null unless attempt detail is available, otherwise the complete retained array for the observed count. Counts, dimensions, per-case verdicts and available metrics must agree with these summaries.                                                                                                                                                                                                                                                |

Complete coverage means observed equals planned attempts and unique observed cases equals planned cases. Incomplete coverage has no available headline pass rate. Without an authoritative coverage source, the adapter must not invent a partial cohort result. A partial report rejected by the existing sanitizer stays rejected.

### Metric availability and units

Available metrics use `availability:"available"`. Unavailable metrics have only `{availability,reason}`, with no numeric value. Availability is `not_evaluated`, `not_applicable`, `not_retained`, or `withheld`; reasons are `no_declared_method`, `incomplete_coverage`, `not_captured`, or `privacy_review`.

- `passRate`: `{unit:"ratio",value,numerator,denominator}`. Available only with complete nonempty coverage; numerator is passed attempts, denominator is total attempts, value is numerator divided by denominator. Not percent units.
- `latencyMs`: `{unit:"milliseconds",p50,p95,max,sampleCount}`. Positive sample count equals observed attempts. Percentiles use the existing nearest-rank method: sorted durations at `ceil(p*n)-1`. Detailed results are cross-checked against retained durations.
- `tokenUsage`: `{unit:"tokens",inputTokens,outputTokens,totalTokens,sampleCount}`. Positive sample count counts observations whose token usage was retained, not all attempts. Zero token sums can be real for captured samples; zero samples means unavailable, not free evaluation. Detailed totals are sums of retained samples.
- `answerAccuracy`, `usdCost`, `uncertainty`: unavailable-only in v1. There is no financial or uncertainty method to invent.

The adapter must validate historical aggregate provenance against operator-supplied expected `suiteId`, `suiteVersion`, `fixtureVersion`, and `catalogSha`. Deriving expected values from the same report is not validation. Do not substitute today's package catalog SHA for historical provenance. The browser compares only matching declared conditions, without ranking them.

## Publication and index JSON

`PublicEvalPublication` has `schemaVersion:"eval-publication.v1"`, `publicationId`, `revisionId`, positive `revision`, `runId`, `dataOrigin`, UTC `publishedAt`, `review`, `supersedes`, and `content`.

- Measured review is `{status:"approved",method:"manual",approvedBy,approvedAt,subjectSha256,record}`. The subject is the entire publication except its root `review` field, including `schemaVersion`. The framework helper `publicEvalPublicationSubjectSha256` hashes compact UTF-8 JSON with recursively lexicographically sorted object keys, original array order and no whitespace or trailing newline. It accepts a publication or its review-free subject and computes a digest, never approval. The exporter must compare the recorded digest with the exact subject before export. This is a framework API, not a contracts/browser runtime API. Approval precedes publication. Synthetic review is only `{status:"synthetic_preview"}` and needs no review digest.
- Revision 1 has `supersedes:null`. Later revisions have `{revisionId,revision,reason:"correction"|"withdrawal",summary}` naming the immediately preceding revision. IDs differ. This is publication correction, not attempt replacement.
- Result content is `{kind:"result",result}` with matching run ID and origin. Correction creates a new linked immutable snapshot, never an overwrite.
- Withdrawal content is `{kind:"withdrawal_notice",reason:"privacy"|"data_integrity"|"owner_request",withdrawnAt,notice}`. It carries no result. Privacy withdrawal removes old result bytes from every public location, including old revisions, leaving only safe notices and references.

`PublicEvalIndex` has `schemaVersion:"eval-index.v1"`, one `dataOrigin`, `generatedAt`, and bounded `publications`:

- Each entry has `publicationId`, `runId`, `review`, `status:"current"|"withdrawn"`, `currentRevisionId`, `summary`, and `revisions`. Review copies the current publication's record; it does not request a second approval. A current summary is `{suiteId,candidate,model,startedAt}`; withdrawn summary is null.
- Each revision has `revisionId`, `revision`, `kind:"result"|"withdrawal_notice"`, `state:"current"|"superseded"|"removed"`, `publishedAt`, `path`, `sha256`. Revision numbers are contiguous from 1, and only the last revision is current. The entry points to it. Paths and hashes identify exact immutable snapshot bytes.
- Superseded correction bytes stay reachable. Withdrawn result revisions are `removed` with null path/hash; only a safe notice is current. No restoration after withdrawal is supported in v1. IDs and reachable paths are unique across the index.

The exporter must compare index records with actual snapshot bytes, IDs, origin, review, chronology and predecessor links. Schema validation alone cannot authenticate review, compute file hashes, resolve references, enforce storage immutability or erase public bytes. Privacy removal is operational work, not proof supplied by a `removed` label.

## Bounds and privacy

Identifiers are 1–128 ASCII characters, start/end alphanumeric, with internal letters, digits, dot, underscore, colon or hyphen. They cannot be paths or email addresses. SHA-256 is 64 lowercase hex characters. UTC timestamps require real calendar dates and optional three-digit milliseconds. Counts and repetitions are bounded at 5,000 attempts and indexes at 1,000 publications. Revision history is nonempty and contiguous, with positive safe-integer counters and no arbitrary revision-count cap. Other integers are nonnegative safe JavaScript integers. Notes are at most 500 single-line characters; snapshot paths are at most 256 characters, relative JSON paths with no traversal, absolute host or URL syntax. Publication and revision identities reject case-folded historical path aliases, including removed revisions.

Safe syntax is not permission to publish identifiers or prose. The framework's existing public-text/address/credential/private-host checks and explicit manual review still apply to every public string. No raw prompts, arguments, results, transcripts, accounts, credentials or free-form grader errors belong in these objects. The browser never redacts private inputs. Schema errors can retain input; keep them private rather than publishing raw decoder diagnostics.

## Synthetic examples

Every fixture is development data, not an evaluation observation or human approval record.

| File under `fixtures/`                                                                     | Purpose                                                                                        |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `synthetic-attempt-capture.json`                                                           | Safe check summaries; an earlier failure and a later pass remain separate planned repetitions. |
| `synthetic-result-aggregate-only.json`                                                     | Aggregate counts without invented case verdicts or discarded attempt detail.                   |
| `synthetic-result-detailed.json`                                                           | Retained attempts, matching counts, nearest-rank latency and token samples.                    |
| `synthetic-result-unavailable-withheld.json`                                               | Conformance counts coexist with withheld detail and unavailable metrics.                       |
| `synthetic-result-incomplete-coverage.json`                                                | Declared plan/status references with missing planned attempts and no headline score.           |
| `synthetic-publication-correction-rev1.json`, `synthetic-publication-correction-rev2.json` | Immutable linked synthetic preview correction.                                                 |
| `synthetic-publication-withdrawal-notice.json`                                             | Safe synthetic withdrawal notice, with no old result payload.                                  |
| `synthetic-index.json`                                                                     | Current correction revision and withdrawn lineage with removed paths/hashes.                   |

Attempt IDs use their JSON tuples. Capture and reachable publication digests use the included two-space JSON bytes plus trailing LF. Report, catalog, configuration and plan/status reference hashes use SHA-256 of synthetic descriptive labels; those source files are not included. The incomplete example assumes a complete local three-case report against a declared five-case plan, not a partial report accepted by the sanitizer. These are standalone DTO examples, not authorized publication inputs or measured evidence.

## Integration status

Source schemas, root exports, regressions and the nine synthetic examples are repository-backed. The [resume handoff](../README.md) records verification status. Contract/package acceptance requires built declarations, real consumer typechecks, behavioral regressions, artifact packing and clean-install artifact verification. Genuine authorized aggregate and new-run evidence remains a separate acceptance requirement; synthetic examples do not close it.
