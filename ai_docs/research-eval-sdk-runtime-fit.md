## Existing evaluator boundary

The required baseline is [`askgina/plugins@ff235a40`](https://github.com/askgina/plugins/tree/ff235a40e9063a3cc6d9846ad7e7c1f3f01a76a6/packages/evals). `runLiveEvalSuite` accepts one `runTrial(input) -> PluginEvalObservation`; adapters belong at that seam, not in another evaluator ([`live.ts` lines 124-143](https://github.com/askgina/plugins/blob/ff235a40e9063a3cc6d9846ad7e7c1f3f01a76a6/packages/evals/src/live.ts#L124-L143)). It permits three to five repetitions, at most 64 cases, one user turn, and catalog tools only.

The v1 target enum has `responses_api` and `codex_cli`, but no AI SDK, HarnessAgent, Claude, or Pi target. Its observation can retain ordered tool names and arguments, optional per-call errors/timing/bytes, available tools, activated skills, usage, final answer, and status ([`contracts.ts` lines 20-27 and 140-172](https://github.com/askgina/plugins/blob/ff235a40e9063a3cc6d9846ad7e7c1f3f01a76a6/packages/evals/src/contracts.ts#L20-L27)). Missing activation evidence is omitted from grading rather than converted to failure. A new target or richer event provenance therefore needs a later contract decision; relabeling a harness run as `codex_cli` would be false.

The repository pins Bun 1.4.x and Effect `4.0.0-rc.111`, with no AI SDK dependency ([root manifest](https://github.com/askgina/plugins/blob/ff235a40e9063a3cc6d9846ad7e7c1f3f01a76a6/package.json#L44-L67)). `@askgina/evals` documents Bun-only support while the candidate packages document Node `>=22`. In-process compatibility is `UNKNOWN`; a later proof must test it or keep a process boundary.

## Evidence consequences and recommendations

Core with shared MCP gives the cleanest cross-provider tool evidence. [`generateText`](https://ai-sdk.dev/docs/reference/ai-sdk-core/generate-text) exposes steps, calls, results, finish reason, and aggregate usage. [`createMCPClient`](https://ai-sdk.dev/docs/ai-sdk-core/mcp-tools) owns discovery and execution. The adapter can emit names, inputs, local durations, final text, and the exact tool map. It must omit token usage unless all three required counts are numeric, and must not invent `activated_skills`, result bytes, requested scope, or a display model. Set Core `maxRetries: 0` to preserve the accepted one-attempt rule; leaving the default of two would hide provider attempts ([request settings](https://ai-sdk.dev/docs/ai-sdk-core/settings#maxretries)). Keep MCP retries at their default zero.

Hosted MCP is not equivalent evidence. OpenAI, Anthropic, or Google may discover and execute remotely, while local callbacks see normalized provider output. Inner-call completeness, timing, server catalog identity, cancellation after provider-side work, and cleanup are not common guarantees. Provider-executed work also cannot be undone by a stream retry. Use a separate target/provenance decision before comparing hosted and host-executed runs.

HarnessAgent normalizes text, tool, usage, and lifecycle events, but does not normalize the fact the evaluator currently calls activation. Its callbacks cannot be a trust boundary because callback errors are ignored, and built-in callbacks describe work after the runtime has completed it ([HarnessAgent lifecycle](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-agent#lifecycle-callbacks)). Sessions own native history and must be ended explicitly; a supplied sandbox remains caller-owned ([session lifecycle](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-agent#session-lifecycle)). These are useful integration APIs, not proof that the installed public plugin activated.

Recommended order for later owner review:

1. Retain native Codex as the activation-bearing baseline.
2. Consider one Core plus shared-MCP adapter for model comparisons, with zero retries and optional fields omitted rather than zero-filled.
3. Treat hosted MCP and each HarnessAgent adapter as distinct candidate targets. Do not pool them until event provenance and activation semantics are versioned.
4. Require a future no-credential compatibility proof for Bun/Node process layout, cancellation, cleanup, bridge event completeness, and version skew. Pin the exact harness-transitive native versions, not whichever CLI happens to be installed.

Remaining proof gaps are measured event completeness, token mapping, abort propagation through each provider and bridge, absence of hidden retries, tool allowlist enforcement before execution, process/sandbox cleanup after timeout, and Claude/Pi activation evidence. Authentication and saved-login feasibility remain owned by the [saved-login report at `7f6e7174`](https://github.com/askgina/plugins/blob/7f6e7174cb3a8589b7f9a65fc95b5a59d0c09bf9/ai_docs/research-eval-saved-login-auth.md); this report only notes that runtime and model authentication are separate boundaries.
