# Write plugin tool justifications

Reviewer reference for askgina/plugins#178. It covers the three write plugins that list in host marketplaces: `ask-gina-spot`, `ask-gina-perps` and `ask-gina-predictions`. Each plugin is a connection to one MCP endpoint and bundles no extra tools. The read-only `ask-gina` plugin is not covered.

## How to read the tables

Each tool lists three annotations the server declares in `tools/list`: `readOnlyHint`, `destructiveHint` and `openWorldHint`. The justification explains why those values are set. Every justification is at most 200 characters, so it fits a marketplace review field.

| Class              | readOnlyHint | destructiveHint | openWorldHint | Meaning                                                                                                                  |
| ------------------ | ------------ | --------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Read, external     | true         | false           | true          | Reads a market, chain or other provider and changes nothing.                                                             |
| Read, Gina account | true         | false           | false         | Reads only state Gina stores for your account.                                                                           |
| Quote or status    | false        | false           | true          | Prepares a quote or checks a transaction. It moves no funds and is not repeatable.                                       |
| Execute            | false        | true            | true          | Submits an order, transfer, leverage or margin update or fund movement. It needs destructive confirmation.               |
| Change settings    | false        | false           | false         | Creates or changes a schedule or allowlist held by Gina.                                                                 |
| Delete schedule    | false        | true            | false         | Ends a recurring automation.                                                                                             |
| Render             | true         | false           | false         | Builds a saved visual artifact from captured refs. `perps.renderDataView` can fetch data, so it sets openWorldHint true. |
| Sandbox            | false        | true            | true          | `bash` runs an isolated workspace shell. It carries the strictest class of the tools it can reach.                       |

Annotations are hints that let a host decide when to ask you. They are not enforcement. Fund moving tools also require the host to confirm the call before it runs.

## Sources

- Perps and Predictions: `tools/docs/venue-tools.json`, which also generates the native tools pages under `docs/perps-mcp/tools.mdx` and `docs/predictions-mcp/tools.mdx`.
- Spot: the annotation mapping in the Ask Gina Spot MCP registry, read on the main branch when this page was written. Spot has no catalog file in this repository.
- Render tools and `bash` annotations come from the same registries.

## ask-gina-perps

Endpoint: `https://askgina.ai/ai/perps/mcp`. The server lists `bash`, every native tool in the table below and the `perps.render*` tools.

Only `createHyperliquidTable`, `executeSqlQuery` and `captureAnalysisDataset` are `bash`-only, because they use sandbox scratch tables. `updateHyperliquidIsolatedMargin`, `fundHIP3Dex` and `returnHIP3DexFunds` are native destructive tools. `host-tools` and `ts-exec` inside `bash` refuse them with `HOST_TOOL_LIVE_CONFIRMATION_REQUIRED`, so the MCP host prompts before each call.

`previewHyperliquidOrderCost` returns a typed `next` suggestion for `placeHyperliquidOrder` when the order can fill, and `fetchHyperliquidCandles` returns one for `perps.renderChart`. A suggestion is never executed by the server. The host shows the call and asks first.
